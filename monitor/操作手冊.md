# Monitor 操作手冊

## 用途

持續監控各Computing Node之健康狀態，於節點故障／恢復時通知Controller，對應論文4-3-1節
Monitor之角色，以及5-2-5節「節點故障情境」實驗中故障事件的偵測來源。

## 運作方式

- 透過Kubernetes API取得目前Computing Node清單（`get_computing_nodes()`，使用
  in-cluster kubeconfig）
- 週期性向Prometheus查詢 `kube_node_status_condition{condition="Ready",status="true"}`
  判斷各節點是否Ready
- 狀態由Ready轉NotReady時，POST至Controller的`/alert`（`alertType: workernode_failure`）
- 狀態由NotReady轉Ready時，POST至Controller的`/noderecovery`
- 執行紀錄寫入 `./logdir/monitor.log`

## 啟動方式

```bash
python3 monitor.py
```

無CLI參數，設定皆為程式內常數（`IN_CLUSTER`、`PROMETHEUS_URL`等），如需連到叢集外的
Controller，需修改原始碼中 `IN_CLUSTER = False` 分支之URL。

## 依賴

- **Prometheus**：叢集內須已部署`prometheus-stack-kube-prom-prometheus`（kube-prometheus-stack），
  Monitor直接查詢其HTTP API，無此依賴則故障偵測完全無法運作
- Kubernetes API存取權限（in-cluster ServiceAccount需有讀取Node狀態之RBAC權限）

## 部署方式

見`monitor-deployment.yaml`／`monitor-service.yaml`。實際部署image版本為
`monitor_mul:2`（2026-05-04起未再更新，屬預期現象——此元件功能單純、邏輯穩定，
不需要頻繁跟著Controller/Agent一起迭代）。
