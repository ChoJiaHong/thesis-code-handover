# Controller 操作手冊

## 用途

系統核心決策模組，對應論文第四章。負責：
- 接收 AgentManager 轉發的使用者訂閱請求（`/subscribe`、`/unsubscribe`）
- 接收 Monitor 回報的節點故障／恢復事件（`/alert`、`/noderecovery`）
- 求解 Problem P（上層GA部署配置 + 下層難易序貪婪前瞻分派），對應候選配置採用決策後
  通知 Agent 更新請求路由與速率
- 內建 EMS（`usc_ts_solver.py`／`svc_updating_decision.py`／`pretrain_sud.py`）與 LSR
  （`lsr_solver.py`）兩個文獻移植 baseline，供實驗切換比較
- 內建 MINLP 精確解模式（`minlp_solver.py`，由`controller_v2.py`之`trigger_solver()`
  於執行期依`solver_mode`動態`import`）：此為`minlp/model.py`＋`run.py`之移植版，
  **需要pyomo/highs**，與`experiments/minlp/`（供5-2-7節複雜度驗證腳本離線使用）
  為同源但不同用途之兩份程式碼，不可混用或誤刪其中一份

## 對外介面（FastAPI，`controller_v2.py`）

| Endpoint | 方法 | 用途 |
|---|---|---|
| `/subscribe` | POST | AgentManager 轉發新使用者訂閱 |
| `/unsubscribe` | POST | 使用者離開 |
| `/alert` | POST | Monitor 回報節點故障 |
| `/noderecovery` | POST | Monitor 回報節點恢復 |
| `/status` | GET | 查詢目前系統狀態（含`solver_mode`，實驗腳本用此判斷輸出目錄）|
| `/config` | GET/POST | 查詢／調整執行期設定 |

## 啟動方式

```bash
uvicorn controller_v2:app --host 0.0.0.0 --port 5000
```

進入容器後在app目錄下執行以上指令

Service對外埠：ClusterIP內部80埠對應容器5000埠（見`controller-service.yaml`）。

## 主要設定檔（`information/`）

| 檔案 | 用途 |
|---|---|
| `controller_config.json` | 主要執行期設定，各欄位意義見同目錄`controller_config_欄位說明.md` |
| `serviceSpec_mul.json` | 服務容量表種子資料（\(W(i,c,j)\)），對應論文4-1-2節 |
| `usc_ts_config.json` | EMS baseline（USC-TS演算法）設定 |
| `q_table.json` | EMS之SUD子模組預訓練Q-table |
| `complexity_experiment_model.json`／`complexity_experiment_subscription_patterns.json` | 5-2-7節複雜度驗證實驗之輸入資料 |
| `aws_prod_serviceSpec_mul.json` | 含AWS節點別名對照表之容量資料，供`complexity_experiment_4_3_5.py`使用 |

**不含**執行期才會產生的狀態檔（節點狀態、訂閱狀態等），需視實際部署環境重新產生。

## 依賴之其他元件

- 需要 `service_yaml/`、`deamonse_service/` 部署好對應之 gesture/pose/object 推論服務Pod
- 需要 AgentManager、Agent 已部署以形成完整請求鏈
