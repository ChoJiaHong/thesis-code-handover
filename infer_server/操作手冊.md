# 推論服務（infer_server）操作手冊

## 用途

實際執行AI推論運算之gRPC服務，對應論文2-3節GPU共享機制與第五章實驗中的
gesture/pose/object三項服務。**三者共用同一份程式碼**，以`SERVICE`環境變數切換：

| 服務 | `SERVICE`環境變數值 | 實際使用之偵測邏輯 |
|---|---|---|
| gesture | `gesture` | `service/gesture_service.py`（SSD模型，`mb1-ssd-best.pth`）|
| pose | `pose` | `service/pose_service_no_batch.py`（YOLOv8-pose，`yolov8n-pose.pt`）|
| object | `pose`（！）| **與pose完全相同之程式碼與模型**，僅部署名稱不同 |

`object`服務並非獨立模型，而是實驗設計上直接沿用pose model、於實驗中視為一個獨立的
邏輯服務（已於論文口試前告知指導教授），此設計已於`controller/service_yaml/object.yaml`
的`SERVICE: "pose"`環境變數中得到驗證確認，非本次交接之程式碼缺漏。

**附帶說明**：`service/pose_service.py`（批次版本）雖存在於本目錄，但目前`main.py`
之`serve()`函式實際上呼叫的是`pose_service_no_batch.py`的`PoseDetectionServiceNoBatch`
（批次版本呼叫已被註解掉），保留前者僅供參考、並非執行期實際路徑。

## 啟動方式

```bash
export SERVICE=pose          # 或 gesture
export GRPC_PORT=50052       # gesture 用 50051、pose/object 用 50052
export QUEUE_TIMEOUT=3
python3 main.py
```

啟動後：
- gRPC服務監聽 `[::]:$GRPC_PORT`（含標準gRPC健康檢查介面）
- Admin API（`admin_api.py`）以獨立執行緒運行於 `0.0.0.0:8000`，提供批次設定查詢／調整

## 主要設定（`config.py` / 環境變數，`env_prefix=""`）

| 設定 | 預設值 | 說明 |
|---|---|---|
| `SERVICE` | `pose` | 服務類型切換 |
| `GRPC_PORT` | `50052` | gRPC監聽埠 |
| `WEIGHTS` | `yolov8n-pose.pt` | pose服務模型權重 |
| `GESTURE_WEIGHTS` | `mb1-ssd-best.pth` | gesture服務模型權重 |
| `GESTURE_LABEL_PATH` | `voc-model-labels.txt` | gesture服務標籤集（VOC資料集標籤）|
| `QUEUE_TIMEOUT` | `1` | 請求佇列逾時秒數 |

## 部署方式

Dockerfile僅為`FROM ultralytics/ultralytics:latest`+`CMD bash`，**實際程式碼透過
`kubectl cp`複製進運行中的pod**、再手動於pod內執行`python3 main.py`（見
`docs/aws_deploy_commands.md`），並非image build時期就固化程式碼。

## 未包含之依賴

`gesture_service.py`背後的SSD物件偵測架構依賴第三方函式庫`vision/`（未隨此repo
提供，需自行取得對應之pytorch-ssd相關實作原始碼並放置於`infer_server/vision/`）。
